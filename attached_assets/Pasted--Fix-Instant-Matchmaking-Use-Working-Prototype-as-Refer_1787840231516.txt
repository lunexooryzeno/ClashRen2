# Fix Instant Matchmaking — Use Working Prototype as Reference

I need you to fix the **Instant Matchmaking** feature in the current ClashRen project.

## Critical reference

The original working prototype is:

`https://github.com/lunexooryzeno/ClashRen_Instant`

**The prototype's Instant Matchmaking flow works correctly.**

The current ClashRen project has the matchmaking UI/feature, but there is a critical bug:

> When Player A and Player B enter matchmaking and are successfully matched, neither player sees **"Opponent Found"** or the matched opponent information.

Do **not** rebuild the entire matchmaking system.

Your job is to identify why the current implementation fails to propagate/display the successful match and fix it using the working prototype as the reference implementation.

---

## 1. First inspect both projects

Before changing anything:

1. Inspect the current ClashRen project.
2. Inspect the `ClashRen_Instant` repository.
3. Find the exact files responsible for:

   * joining matchmaking
   * creating/joining a queue
   * detecting when 2 players are matched
   * updating match status
   * notifying both players
   * polling/WebSocket/SSE/realtime communication
   * displaying "Opponent Found"
   * redirecting/showing the matched opponent
4. Compare the working prototype implementation against the current implementation.

Do NOT make broad architectural changes before understanding the difference.

## 2. Reproduce the bug

Test the current implementation with two separate players/sessions.

Example:

Player A:

Expected:


## 6. Important state requirements

When two players are matched, BOTH clients must independently detect the match.

For example:

```text
Player A:
status = matched
matchId = XXXXX
opponent = Player B

Player B:
status = matched
matchId = XXXXX
opponent = Player A
```

Do not rely on only the player who triggered the pairing request receiving the result.

The matchmaking backend must create a persistent match result/state that both clients can retrieve or receive.

* frontend polling the wrong endpoint

* stale React/state values
* incorrect player ID
