PHASE 4 — MATCHMAKING BACKEND
=============================

Build the matchmaking logic on the ClashRen2 backend.

Do not implement matchmaking as frontend-only state.

The server must be authoritative.

A player joining the queue should create a server-side matchmaking record.

The server should safely pair compatible players.

At minimum, matchmaking should consider:

* game mode
* entry amount
* player eligibility
* queue status
* existing active match
* account status

Prevent:

* duplicate queue entries
* matching a player with themselves
* double matching
* joining multiple incompatible queues
* race-condition pairing
* two matches being created for the same player

The matchmaking operation must be safe against concurrent requests.

Use database transactions/appropriate locking or another reliable server-side mechanism where required.

Do NOT rely on:

setTimeout()
frontend timers
localStorage
React state
client-side random matching

for authoritative matchmaking.

===================================

IMPORTANT:

balance = balance - entryFee

The existing wallet/diamond architecture must be inspected first.

If not, create the correct foundation rather than a temporary balance hack.

Every financial transaction must be traceable.

The system must prevent double charging.

Use idempotency where appropriate.

Do NOT implement real-money payouts yet unless the existing system already supports secure settlement.

For this phase, the priority is a safe matchmaking foundation.
